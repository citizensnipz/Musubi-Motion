# Texture Assets

Use **File > Import Texture** or **View > Texture Assets**. Select one PNG, JPEG, or WebP file, inspect the pending swatch and dimensions, then **Apply image**. **Cancel preview** or Escape in the preview leaves the scene unchanged. Ordinary File > Import and viewport drops also accept a single image. The dock supports both themes, keyboard focus and narrow layouts.

The browser lists reusable swatches with filename, dimensions, format, original byte size, alpha presence, content ID, default role and material references. Color means sRGB; Data means Raw. This is the default for future texture consumers. Existing mesh slots retain their established interpretation: base color and emissive use sRGB; normal, alpha, roughness, metalness and bump use Raw. Changing the library default does not reinterpret an existing FBX material.

**Replace image** stages another original image and atomically swaps all material references when applied. If the replacement content already exists, it reuses that asset. **Relink material references** directs the selected image's existing material slots to another imported image. **Delete unused** is disabled while materials reference the image. Relink first, then delete. Every applied import, replacement, role change, relink and deletion supports Undo/Redo; reimporting identical content adds no undo entry. Library selection and pending previews are transient.

FBX imports share the same content-addressed registry. The existing FBX importer captures its local image data, then the editor adopts supported embedded images into the library and replaces inline material images with asset references. UV channel, wrapping, repeat, offset, center, rotation, flipY and material slot semantics are preserved. An existing FBX image that cannot enter the bounded library remains embedded in its material, with an explicit import warning. No filesystem or network URL is saved or fetched. Standalone library images are not automatically assigned to meshes; material assignment is TASK-023.

Limits are explicit: 16 MiB per original image, 8192 pixels per side, 16,777,216 pixels, 512 library entries and 64 MiB total original image bytes. Header dimensions are checked before pixel allocation. PNG chunk integrity, complete data and still-image restrictions are validated; animated PNG/WebP and JPEG EXIF rotation/mirroring receive actionable export/normalize errors. The browser verifies decoding and alpha. Swatches are at most 128 pixels; temporary canvas/image resources are released. Distinct originals retained in texture undo history are capped at 128 MiB (the editor also retains its existing 100-step limit); older undo entries are released as needed. Encoded strings and browser overhead are additional memory, so these byte limits are not a total heap guarantee.

Save/reopen embeds one original per content ID plus its small swatch in the current scene JSON. Scene version 2 and MSB container version 1 remain unchanged; the optional dictionary is an additive extension. Original bytes are immutable. Failed imports and failed native opens are staged and preserve the current scene. Opening checks library hashes, bounds, references and browser decoding before replacing the live scene. Library images remain available after deleting the scene objects that used them.

The original example [texture-library.msb](../examples/textures/texture-library.msb) contains a textured card and [musubi-checker.png](../examples/textures/musubi-checker.png), a 16x16 RGBA checker authored by the generator. Regenerate with `node scripts/generate-texture-example.mjs`. No downloaded artwork, model, texture dataset, new dependency or license obligation was introduced. Implementation uses existing Three.js 0.180.0 (MIT), Spark 2.4.0 (existing renderer; no changes) and @noble/hashes 2.4.0 (MIT), plus browser image/canvas APIs.

Maya mapping follows Autodesk Maya 2024 [Hypershade Browser](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-LightingShading/files/GUID-CA8C895B-496A-40C3-9B91-8356E04931C8.htm) swatches and [file-input color management](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-Rendering/files/GUID-A84A137B-CB0B-4BAA-A271-5A3FFF448143.htm). Musubi uses a compact contextual dock and familiar color/data labels. Browser adaptation uses explicit local file selection and portable images in place of filesystem paths. No new shortcut, viewport selection, gizmo interaction or numeric editing gesture is introduced. Existing import icon is reused; action buttons are clearly labeled text, with no new icon artwork.

Production-browser verification on Chromium 149 / Ryzen 9 9900X / 24 logical cores / 62 GiB covered PNG/JPEG/WebP, exact preview cancel, role undo/redo, dedup, replacement/relink/protected-delete, native MSB save/offline reopen, corruption rejection and dark/light/720px layouts. A 2048x2048 flat PNG import through swatch and Apply took 123-166 ms across the measured runs; this is one local smoke measurement, not a maximum-size or general performance guarantee.
