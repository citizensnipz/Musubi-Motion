# Individual splat selection

Select one loaded splat object, then **Select → Splat Components** or **F8**. The dockable Splat Components panel shows the selected and original source counts. Click a center (8 CSS px tolerance), or drag an inclusive box. **Shift** toggles, **Ctrl** subtracts, **Ctrl+Shift** adds; macOS Command substitutes for Ctrl. All, None and Invert are in the panel and Select menu. F8 or Object Mode exits. Selecting another object, joint, mesh component or skin tool ends this mode.

**Through** scans original centers regardless of overlap. **Front centers (approximate)** retains the nearest original center within each fixed 4 CSS px screen cell of the active object. This is a bounded center-depth approximation, not Gaussian alpha compositing, ellipsoid coverage, backface tests, mesh/other-object occlusion, or a renderer depth readback. The highlighted points intentionally show selected centers through surfaces. They are markers, not recolored Gaussian footprints. A camera change can alter the screen-cell grouping. Front mode rejects viewports exceeding 2,000,000 cells.

Click/box excludes centers outside the camera clip volume and source opacity multiplied by mesh opacity below Spark's `minRaycastOpacity`. All/Invert include offscreen originals meeting that opacity threshold, matching the ordinary meaning of selecting all components. Original stable IDs are the source asset ID plus original index, scoped to the active shape instance. GPU sorting, LoD indices and elastic generated fill are never selection identities. Skinned centers use the existing CPU adapter that matches Spark 2.4.0 linear blend transforms and rounded 8-bit weights; elasticity preserves original centers and augments scales/fill, so editable originals match displayed originals. Arbitrary future GPU position modifiers require a corresponding evaluated-position adapter.

Selection and GPU highlight resources are transient and excluded from scene/archive/history. No transform, delete or key command is supplied for splats in this slice. Object manipulators, object Delete/Backspace/S and object property transform editing are guarded while this mode is active. Exit it before editing the object. Existing skin-weight and mesh component modes remain independent.

Scans read 4,096 positions per chunk and yield to the UI between chunks. Escape, Cancel Scan, pointer cancellation, blur, wheel/camera changes, pose changes, scene edits and mode changes abort without applying a partial result. Pointer-down snapshots also reject a changed view before release. Escape retains the preceding selection and mode. A selection is limited to 1,000,000 originals, including union/toggle results; exceeding it reports an error and retains the preceding selection, without truncation. IDs use a compact sorted Uint32Array (400,000 bytes for 100k IDs; at most 4,000,000 bytes). Highlights independently show at most 20,000 deterministic evenly sampled markers, explicitly labeled in the panel and viewport count. Membership and All/Invert always include every selected ID. Preview memory is fixed at 240,000 bytes for position storage; scan working position arrays are 49,152 bytes per chunk plus result/front-cell bookkeeping. Set operations use linear sorted-array merges rather than a large membership Set.

Reproduce with `node scripts/generate-splat-selection-fixture.mjs`, then import `examples/splat-selection-regions.splat`. It has 433 original records: three 12×12 regions at two depths and one transparent center. The generator and data are original Musubi code/assets; no new dependency or external data/license obligation. Existing Three.js 0.180.0 and Spark 2.4.0 APIs are reused.

Maya mapping: [Select objects/components](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-Basics/files/GUID-5C5F2B9B-BE16-4C49-B72B-70EA7CB4C688.htm), [Maya 2026 selection preferences](https://help.autodesk.com/cloudhelp/2026/ENU/Maya-Customizing/files/GUID-8C8BA1F4-59EE-4A02-BFE7-9193C0D6F5BE.htm), and [camera-based selection](https://help.autodesk.com/cloudhelp/2024/ENU/Maya-Basics/files/GUID-72C0C337-FBA7-4009-9D91-57D0587A17BA.htm). Musubi uses Select menu, F8, contextual component panel and Maya selection modifiers. The explicit approximate front-center mode is a deliberate Gaussian/browser adaptation; it does not claim Maya's unobstructed polygon-component semantics. Text editing retains native input keys. No numeric fields, custom artwork or Autodesk assets are introduced.
